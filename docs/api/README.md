# API contracts

## Implemented local routes

| Route | Purpose | Access |
|---|---|---|
| GET /metrics | Prometheus-format process metrics | Read |
| GET /health/live | Process liveness | Public |
| GET /health/ready | Reader database connectivity | Read |
| GET /v1/status | Capabilities and latest complete collection receipt | Read |
| GET /v1/sources | Paginated sources | Read |
| POST /v1/sources | Register a source idempotently by code | Collector |
| POST /v1/collections | Atomically persist a collection and observations | Collector |
| GET /v1/collections/{collection_id} | Receipt, accepted, eligible and incomplete counts | Read |
| GET /v1/signals | Paginated observations with server-derived eligibility | Read |
| GET /v1/webhook-receipts/{receipt_id} | Webhook processing status | Read |
| POST /webhooks/tradingview | Durable webhook receipt | Dedicated webhook credential |
| GET /v1/data-quality | Bounded collection and observation quality counts | Read |
| GET /v1/reports/daily | Daily report by collection date: simulated portfolio, signal progress and target hit rates | Read |
| GET /v1/selection/candidates | Candidates of one assisted selection session with decisions, slots and baseline order | Read |
| POST /v1/selections | Confirm atomically the decisions for every pending candidate of one session | Collector |

Use `Authorization: Bearer <API_READER_TOKEN>` for reads and the distinct `API_COLLECTOR_TOKEN`
for writes or reads. Missing/invalid credentials return 401; reader writes return 403.
Invalid input returns 422 with field paths and error types, without submitted values. Missing identities
return 404, identity/currency conflicts 409, bodies exceeding 1 MiB 413, and database failures a generic
503. The error envelope uses `error.code`, except authentication errors which use FastAPI's `detail`.
Successful registrations return 200 after commit, including retries. No delete operation is exposed; the only updates are tracking-run cancellation and the confirmation of pending candidate decisions.
Public OpenAPI, Swagger and ReDoc routes remain disabled. The application exposes its schema programmatically.

## Sources and queries

Source registration accepts `code` (lowercase slug, maximum 64 characters) and `name` (160 characters).
Whitespace is stripped. The same code/name returns the existing ID; changing the name returns 409.
Register `tradingview` explicitly to use the initial analyst-label mapping. No sources are seeded.
Source listing accepts `limit` (1 to 100, default 20), `offset` (0 to 10000), and optional `code`.
It returns `items`, `limit`, `offset`, `has_more`; source items contain only `id`, `code`, `name`.

Signal queries accept the same pagination bounds, optional `collection_id`, `source_id`, `instrument_id`,
and `eligible_only` (default false). Ordering is observed time descending, then UUID. Each item returns
its observation/collection/instrument identities, signal kind, source symbol, original and normalized rating,
price, daily change, observed time, parse status and eligibility. Decimal outputs are JSON strings.
Pagination spans current data and is not a snapshot across separate requests.

Quality queries accept `days` (1 to 31, default 30) and optional `source_id`. The response reports the UTC
`since` and `as_of` bounds, collection/partial/failed counts and observation/incomplete counts, using collection
observation time. `scheduling_assessed` and `price_coverage_assessed` remain false. Zero counts do not prove
complete collection or price coverage. Status reports implemented capabilities and the maximum receipt time
of a collection declared complete. These endpoints do not verify provider availability or market outcomes.

## Collection contract

```json
{
  "schema_version": 2,
  "client_collection_id": "01924c69-564d-4ee4-a948-cf3b48a0f334",
  "source_id": "4c14a1e4-0c90-4f71-9397-b79f74e2c8eb",
  "source_url": "https://example.invalid/synthetic",
  "observed_at": "2026-10-07T20:00:00Z",
  "market_session_date": "2026-10-07",
  "status": "partial",
  "source_total": null,
  "rows_examined": 40,
  "filters": {},
  "observations": [{
    "exchange": "SYNTH",
    "symbol": "TEST1",
    "currency": "BRL",
    "source_symbol": "SYNTH:TEST1",
    "signal_kind": "analyst_consensus",
    "source_column": "Analyst rating",
    "original_rating": "Viés de alta forte",
    "observed_price": "10.25",
    "daily_change_percent": "-2.5",
    "observed_at": "2026-10-07T20:00:00Z",
    "source_published_at": null,
    "raw_evidence": {}
  }]
}
```

Replace the synthetic source ID with a registered source. Client IDs are UUIDs; stored primary keys are
random UUIDs generated by PostgreSQL. Timestamps require an offset and normalize to UTC. Under the
automatic policy session dates are collector assertions. Under the assisted policy the service derives the
session from `observed_at` and `trading_days` in America/Sao_Paulo (that day once its session opened,
otherwise the previous open day) and rejects a different `market_session_date` with 422
`market_session_date_mismatch`, an `observed_at` more than two minutes ahead of its clock with
`collection_observed_in_future`, and uncovered dates with `market_calendar_unavailable`. This is a clock and
calendar convention; it cannot prove that the page had already updated. Numeric input uses decimal notation;
ambiguous localized text belongs in `raw_evidence`, with the corresponding numeric field null.

`schema_version` is `3` or `2` and required; version 1, in which the collector sent every row of the list,
is rejected as an invalid request. Version 3 adds optional `volume` (displayed share volume, a non-negative
integer) and `sector` (displayed label, at most 120 characters); version 2 rejects them. The stored hash of
a version 2 payload is computed exactly as before, so a retry of a payload accepted before this change is
still recognized as a duplicate. The collector examines the whole list and sends only the qualified rows.
`rows_examined` is required and records how many rows were examined; it cannot be smaller than the number of
observations. Status is `complete`, `partial` or `failed` and describes the examination, not the number of
rows sent. A complete collection with a `source_total` must have `rows_examined` equal to it. A complete
collection may carry no observation at all, which records that the list was read and nothing qualified.
Failed collections cannot contain accepted observations.

Only eligible observations are persisted. Before inserting anything the service applies the eligibility rule
below to every row; if one row fails it, the request is rejected with 422 `observation_not_eligible` and
nothing is stored, including the collection itself. Rows are never dropped silently.

A collection accepts at most 2000 observations within the body limit. Duplicate exchange/symbol/signal-kind
rows in one request are rejected. Exchange and symbol use uppercase identifiers, currency three uppercase
letters. A missing price is allowed and produces an incomplete observation. Prices must be positive, changes
at least -100%, and precision must fit the database.
Filters and raw evidence accept at most 20 text entries, each value at most 2000 characters. Unknown input
fields are rejected. Source URLs require HTTP(S), reject embedded credentials, and are stored without fetching.

For source `tradingview` and kind `analyst_consensus`, mapping `tradingview-analyst-v1` recognizes Strong Buy,
Viés de alta forte, Buy, Neutral, Sell and Strong Sell, ignoring label case and surrounding whitespace.
Only Strong Buy analyst observations with a negative daily change are eligible. A missing observed price
marks quality incomplete but does not change this selection rule. Technical ratings never qualify, whatever
their label. A missing rating, a label the mapping does not turn into Strong Buy, and a missing, zero or
positive daily change are not eligible. The other labels of the mapping are recognized only to be refused;
the mapping is not extended for ratings that are not stored.

Receipts return `source_total`, `rows_examined`, `observation_count`, `eligible_count` and
`incomplete_count`, plus `selection_policy` (`automatic` or `assisted`), `experiment_version`,
`candidates_pending`, `candidates_already_tracked`, `candidates_not_monitorable`, `candidates_cap_reached`
and `selection_slots_remaining` (null under the automatic policy). The candidate counts describe the
instruments of that collection and are read when the receipt is produced, so they can change after a
selection. For collections of version 2 `eligible_count` equals `observation_count`. Collections
stored before version 2 have a null `rows_examined` until pruned; see [operations](../operations.md).

The service stores a SHA-256 of the validated payload with sorted object keys and normalized timestamps.
The unique `(source_id, client_collection_id)` identifies retries. Identical validated content returns the
original receipt with `duplicate: true`; changed content returns 409. Preserve row order and decimal spelling
when retrying. Concurrent identical retries produce one collection. Instrument identities are shared by
exchange/symbol; a contradictory currency rejects the entire transaction, including newly inserted rows.
No partial persistence or acknowledgement before commit is allowed.

## Tracking, quotes and hits

Under the automatic policy, registering a collection creates one `prepared` tracking run for each eligible
observation whose instrument has no `prepared` or `active` run in the same experiment, across all experiment
versions. Later eligible observations are stored as signals and reuse the open run; they never reset its
reference, window or levels. Runs are created only inside the transaction that inserts their origin
observation, so a retried collection or an already stored observation cannot create another run. Under the
assisted policy no run is created at registration; runs are created by `POST /v1/selections`, see below.
An observation that already originated a run cannot originate another.

| Route | Permission | Purpose |
|---|---|---|
| `GET /v1/tracking-runs` | Reader | Runs with status, admission, reference, window and level counts |
| `GET /v1/quotes/latest` | Reader | Latest accepted quote per instrument |
| `GET /v1/trigger-events` | Reader | First observed hit per level |
| `POST /v1/tracking-runs/{id}/cancel` | Collector | Idempotent cancellation |

All list routes accept `limit` (1 to 100, default 20) and `offset` (0 to 10000) and return `items`, `limit`,
`offset`, `has_more`. Tracking runs filter by `status` (`prepared`, `active`, `completed`, `cancelled`,
`expired`) and `instrument_id`. Latest quotes filter by `instrument_id`. Trigger events filter by
`tracking_run_id` and `instrument_id`. Decimal outputs are JSON strings.

A run with `admitted_at` null is waiting for a monitoring slot. A `prepared` run with `admitted_at` set is
monitored but has no reference yet; its reference fields stay null rather than holding an invented price.
`price_coverage` is `partial` for polled runs. Quotes report `quoted_at` (provider market time) separately from
`received_at`. Events report `evidence_kind` (`price_quote` or `webhook`), the threshold, the observed price
and `evidence_quality`. Polled hits are `coarse`: `occurred_at` is the time of the quote that first showed the
level reached, not the moment the price touched it.

Cancellation turns a `prepared` or `active` run into `cancelled` and frees its slot. Repeating it returns the
same run. A `completed` or `expired` run returns 409 `tracking_run_closed`; an unknown ID returns 404
`tracking_run_not_found`. There is no reopen operation. Under the automatic policy a later eligible
observation creates a new run; under the assisted policy a new run needs a later selection, and cancelling a
selected run does not free its selection slot.

No detected hit does not prove that the price never touched a level between two polls, after the last poll of
a session or in data the provider published late. Do not report silence as a verified non-hit.

## Assisted candidate selection

Policy of a session. Experiment version 2 adds `candidate_selection` rules (three new runs per session,
criteria `selection-v1`, reference after the decision, late decisions allowed and marked). The version that
governs a session is the one stored on its first collection (`collection_runs.experiment_version_id`). A
session whose first collection predates that column follows the latest version without selection rules; a
session with no collection yet follows the latest version. So applying the migration changes behavior only
from the first session without an earlier collection, and a session never mixes policies or gains extra
slots. Registration takes a transaction advisory lock per session date.

Registration under the assisted policy stores every eligible observation and one decision per
(version, session, instrument). A later collection of the same session adds observations to an existing
decision. The initial decision is set by the service: `already_tracked` with the open run when the instrument
has one in the experiment, `not_selected` with `not_monitorable` when the quote client rejects the ticker
format, `not_selected` with `daily_cap_reached` when the session has no slot left, otherwise `pending`.

`GET /v1/selection/candidates` (MCP `list_selection_candidates`) takes an optional `market_session_date`,
defaulting to the latest session collected under the assisted policy. It returns 404
`selection_session_not_found` without a collection and 409 `session_not_assisted` for an automatic session.
It reports slots used and remaining, the next session opening and whether a confirmation now would be late,
every collection of the session, and each candidate with its observation, decision, current open run for
pending candidates, `estimated_turnover_at_observed_price` (observed price times displayed share volume, an
estimate and not the traded value or a daily average, flagged `turnover_partial_session` before the close)
and `baseline_rank`. The baseline uses the estimate only when every pending candidate has price and volume
from the same collection (`liquidity_comparable`); otherwise, and as a tiebreak, it orders by the SHA-256 of
`session date:symbol`, a stable administrative order with no financial meaning. A session with collections
and no candidate returns an empty list; nothing needs to be confirmed. The whole response comes from one
repeatable-read transaction, so its candidates, counts, slots and collections describe the same moment. It
can be outdated once delivered; the confirmation revalidates the current state.

`POST /v1/selections` (MCP `confirm_selection`) takes `client_selection_id`, `market_session_date`,
`criteria_version`, `ranking_basis` (`full` or `limited`), `summary`, `no_selection_reason`,
`plugin_version` and one decision per pending candidate with `outcome`, `reason_code`, `rank`, `rationale`,
`event_date`, `evidence`, `unavailable` and `risks`. In one transaction, after the session lock:

1. Same identifier and hash return the stored receipt with `duplicate: true`; changed content returns 409
   `selection_identity_conflict`.
2. `criteria_version` must match (409 `criteria_version_mismatch`). The decisions must be exactly the
   current pending set: 409 `nothing_pending`, `candidate_already_decided` or `pending_set_changed`, 422
   `decision_not_in_session`.
3. Selected candidates cannot exceed the remaining slots (409 `selection_exceeds_slots`). While a slot stays
   empty no candidate may be only `outranked` (409 `selection_underfilled`); every other non-selected
   candidate carries an impediment code and a rationale. Ranks are contiguous from 1 across selected and
   outranked candidates, selected ones first. Zero selected requires `no_selection_reason`.
4. The instruments of selected and claimed `already_tracked` candidates are locked in instrument order and
   checked: a selected candidate with an open run rejects the whole request (409
   `candidate_already_tracked`); an `already_tracked` claim without one is rejected (409
   `already_tracked_not_confirmed`). Nothing is converted or promoted automatically.
5. The service reads `clock_timestamp()` after these validations as `decided_at`, rejects evidence consulted
   more than two minutes later (422 `evidence_after_decision`) and marks the selection `late` when
   `decided_at` is at or after the opening of the session that follows the collected one.
6. Runs are created for the selected candidates with `created_at` set to `decided_at`, slots are taken in rank
   order, and every decision stores rank, baseline rank, rationale and details (evidence with source, dates
   and consultation time, unavailable information, risks, ranking basis, and for
   `price_comparison_invalid` the `event_date` with the note that the tracking window was not known).

The service enforces limits, identity, states and the presence of justifications; it does not judge the
interpretation. Unique keys on (version, session, instrument) and (version, session, slot) back the limit in
the database. The receipt lists selected symbols with slot and run, counts, `decided_at`, `late` and the
current `slots_remaining`. Reason codes: `not_selected` takes `outranked`, `trading_halted`,
`price_comparison_invalid` or `other_concrete_impediment` (the two first need a dated source,
`price_comparison_invalid` also `event_date`); `not_assessable` takes `essential_data_missing` or
`identity_unresolved`.

For runs of a version with `reference_after_decision`, the monitor accepts as reference only a quote whose
market time is not earlier than the run's `created_at`, the decision instant. A late quote received after
the decision but timed before it does not activate the run. Runs of version 1 keep their rule unchanged.

## Diagnostic identifiers

Every HTTP response carries `X-Request-ID`. Captured server errors also carry `X-Error-ID` while retaining
safe error bodies. Unexpected failures return 500 with `internal_error`; database failures remain 503.
Use these identifiers with `make errors ID=...`. See [observability](../observability.md).

## Daily report

`GET /v1/reports/daily` and the MCP tool `daily_report` call the same read-only service. The report always
describes the current state: it runs in one repeatable-read transaction, returns `generated_at` and uses
only quotes and events recorded up to that instant. There is no historical `as_of`; the portfolio engine
accepts a cut internally and is tested with past cuts, but the interface always uses `generated_at`. Pages requested at
different moments are not one snapshot.

Query: `limit` collection dates (default 10, at most 30) and `offset`, newest first; optional
`market_session_date` to read one date; `signal_limit` (at most 100) and `signal_offset` to page the rows of
one date, which requires `market_session_date`. Top level `has_more` reports older dates. Each date carries
`signals_has_more`. Totals and rates of a date always cover the whole date.

Rules, all computed by the service:

- Groups are collection dates (`market_session_date`). Each carries `selection_policy` and
  `experiment_version`. Under the automatic policy only eligible observations are counted as signals.
- Under the assisted policy each candidate is one row and `signals` counts candidates. Rows carry
  `selection_outcome`, `selection_reason`, `selection_rank`, `selected_at` and `selection_late`, and
  `tracking_link` is `own` for selected candidates, `already_tracked` with the existing run, or
  `selection_pending`, `not_selected` or `not_assessable`. The `selection` block counts collections by
  status, eligible observations, candidates, new candidates, already tracked, selected on time and late,
  not selected by reason, not assessable and pending, and lists each confirmed selection. `horizons` and
  `target_order` cover selections confirmed on time; `late_horizons` and `late_target_order` cover late ones,
  never added together. `selection` is null and the late blocks are empty under the automatic policy.
- A signal is `own` when a tracking run was created from that observation. It is `reused_confirmed` only
  when exactly one other run of the instrument was admitted before the observation was stored and is
  provably still open after it: open now, expired with a later `expires_at`, or completed with its last
  event recorded later; and no other run of the instrument was created in between. Anything else, including
  a cancelled or never admitted run, is `unconfirmed`. Rates use `own` runs only, so they describe the runs
  started by that date, not every stock listed that day.
- D+0 is the session of `reference_at`; D+N is the Nth following session of `trading_days`. The 20 session
  window ends at D+19. D+20 is reported as `out_of_window`.
- A run uses only quotes of its instrument and reference source, timed from `reference_at` to the earliest
  of `generated_at`, `expires_at` and, for a completed run, the time of its last recorded hit. A completed
  run whose hits are not all timed quote evidence, and a cancelled run, use no quotes, because their end
  cannot be dated. Quotes of a later run of the same instrument are never used for an earlier one.
- Milestones 1, 2, 5, 10, 19 and 20 have a state: `future`, `in_progress` (provisional, last quote so far),
  `final` (last accepted quote of that session), `no_data`, `out_of_window`, `not_available` (cancelled) or
  `calendar_unavailable`. A past milestone is never filled with a later quote. Returns are
  `(price / reference - 1) * 100`, two decimals, and are polled quotes, never closing, highest or lowest
  prices.
- Rate sample for a horizon, independent of the outcome: the run is `own`, has a reference, is not
  cancelled and has at least one accepted quote in every session from D+0 to D+N, including the D+N session
  itself while it is in progress, where the quote must exist by `generated_at`. A run with earlier hits but
  no quote yet in the session in progress is excluded for coverage, and its hits are reported outside the
  sample. This is a minimum sampling criterion, not complete coverage: it sets no number, frequency or age
  of quotes. A run completed with all six
  hits timed needs that coverage only up to its completion session and stays in later horizons, counted in
  `completed_early`; this applies to targets only, never to returns.
- A target is a hit when its event has `occurred_at` up to the horizon close, or up to `generated_at` while
  the horizon is open. An event without `occurred_at` makes that target `indeterminate` for the run and
  removes it from that target's denominator. No event means not observed, not proof of no touch.
- Each run is placed in a horizon by its own D+N session, so one collection date can hold runs in different
  positions. Before that session opens the run is counted in `future_runs` and is in no denominator. While
  the session is in progress it is in the `partial` block. After the close it is in the `concluded` block.
  The partial denominator holds every run in the sample at that moment, not only those that already hit. A
  run completed early enters a horizon only when that horizon's session arrives.
- Every target reports `hits`, `denominator`, `rate_percent` (one decimal, null when the denominator is
  zero), `indeterminate` and `proven_hits_outside_sample`, the timed hits of runs excluded as cancelled or
  for coverage. Blocks report the exclusion counts.
- `target_order` compares the +2% and -2% events of a run: `up_first`, `down_first`, `only_up`, `only_down`,
  `neither`, `indeterminate` (missing time, unknown evidence quality or equal times) or `not_assessed`
  (cancelled). It is the order of observations; the real order between polls is unknown.

Not available: D+20, quotes after completion, expiry or cancellation, the time of a cancellation, a report
as of a past instant, and a link between a signal and a run that was cancelled or never admitted.

### Simulated portfolio

Each date carries an optional `portfolio` object, computed in the same transaction with `generated_at` as the
cut. It is filled on the first row page of a date (`signal_offset` 0) and null on later pages. The top level
`portfolio_semantics` states its limits. The capability `portfolio_simulation` in `/v1/status` announces it;
older consumers can ignore the field. Rules are in [experiment](../experiment.md#simulated-portfolios).

- `cut_at`, `simulation_version` (`exit-v2`), `initial_capital` (100000.00), `provisional` and
  `latest_quote` (symbol, price, `quoted_at`, `received_at`) of the participants, among quotes with a known
  receipt time.
- `composition`: `status` (`empty`, `provisional`, `final`), `first_entry_at`, `participants`,
  `outside_portfolio`, `allocation_per_participant` and `rounding_residual`.
- `strategies`: `A` to `I` and `HOLD`, in that order, with `target_percent`, `stop_percent` and
  `added_in_version` (`exit-v1` for A, B, C and HOLD, `exit-v2` for D to I, which are rebuilt
  retrospectively for earlier dates), each with a
  `trigger_price` block (exit at the trigger price) and a `first_quote` block (exit at the first recorded
  quote that reached it). A block has the counts `exits_target`, `exits_stop`, `open`, `window_closed`,
  `pending_entry`, `observation_ended` and `unproven`; the amounts `realized`, `unrealized`, `cash` and
  `open_value`; `complete`; `equity`, `result` and `result_percent`, null when `complete` is false;
  `affected_capital` and `affected_positions`; `minimum_coverage_missing_capital` and
  `minimum_coverage_missing_positions`.
- `triggers`: symbol, strategy, `exit_kind`, `trigger_percent`, `trigger_price`, the crossing quote with
  market time and receipt time, and the result under both prices.
- `positions`: participants and stocks confirmed after the first entry (`outside_portfolio`, no capital),
  with `decided_at`, `selection_late`, `recorded_risks`, `allocation`, `display_quantity` (display only),
  `entry` (price, `quoted_at` and `received_at`; `received_at` is null when the reference quote cannot be
  found, and no other time is substituted), `pending_reason`, `observation_end`, `observed_until`, `window_ends_at` and one entry per strategy
  with `state`, trigger, exit quote or last valuation, values and results under both prices,
  `minimum_coverage` and `sessions_without_quote`.
- `equity_by_session`: per session from the first entry to the cut or the last window end, its `state`,
  `valued_at` and, per strategy, the equity under both prices, null with `positions_without_quote` or
  `positions_unobserved` when it cannot be determined. Each point uses only references, exits and quotes
  quoted and received by its `valued_at`, not by `cut_at`, so a quote received after a close first counts at
  the next point.
- `limitations`: codes for the conditions present in that portfolio.

Amounts are Decimal strings rounded to cents. Prices are Decimal strings with eight decimals.
